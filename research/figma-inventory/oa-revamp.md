## OA framework (8890:7129) — canonical structure

**Principles**

- Limited attention: an OA card shows max 2 signals (sub-service + one context, e.g. CabXL_Company, Auto_Premium, Sedan_Intercity). Not allowed: CabXL_Company_Premium, CabXL_Premium_Intercity.
- Prioritisation: only the highest-priority signal is emphasised. Preference themes > Contextual themes > Base service. Preferences: GTA > SIA. Exception: Corporate/Company can override everything (exceptions must be agreed).
- Separation: Base service = minimum & most common; Sub-service = what the job is; Contextual = why it matters; Preference = what captain wants.
- No free visual weight: no icon/theme unless qualified through the framework; every new order/service must fit one bucket.

**Buckets**

| # | Bucket | Definition | Differentiation | Priority |
|---|---|---|---|---|
| 1 | Base Service | Primary category (vehicle type) | none - no icon, no theme |  |
| 2 | Sub-Service | How the job is executed | service icon only (top-right 72x82 icon + chip icon) |  |
| 3 | Contextual Orders | Why this order needs attention | Theme, Theme+Icon, or Theme/Icon | Company > Intercity > Priority |
| 4 | Captain Preferences | Orders aligned with captain intent | Theme, Theme+Icon, Theme/Icon | GTA > SIA |

**By service**

| Service | Base (no icon/theme) | Sub-service (icon) | Contextual (theme+icon) | Preference (theme+icon) |
|---|---|---|---|---|
| Bike | Bike Taxi | Bike Lite, Scooty, Bike Pink, Food Delivery, Ownly Food, Bike Parcel Delivery, Scooty Parcel Delivery, Grocery Delivery | Company, Intercity, Priority | GTA, SIA |
| Auto | Auto, E-Rickshaw | Auto Plus, Auto Priority, Auto Line, Auto Share, Auto Pet, Auto Parcel, Local Auto, Auto Lite, Seat Share | Company, Intercity, Priority | GTA, SIA |
| Cab | Cab - Economy Non-AC | Cab Eco-AC, Cab Sedan AC, Cab Sedan Non-AC, Cab XL, Cab Share | Company, Intercity, Priority, Airport | GTA, SIA |

- **Parcel/Food/Grocery**: not a separate service: sub-services of Bike (and Auto Parcel); parcel 'Icon + Theme' experiment (June '26) would conflict with 'sub-service creating theme' rule
- **Intercity**: contextual bucket (theme: sky/cloud gradient header + destination city + distance/duration); local Service Chip has Base Service=Intercity (Eco/Pre/XL Intercity) - conflicts with framework
- **Multistop**: not in framework (Jan '25 design uses '2 Stops' pill on route)

**Non-allowed:** Contextual without qualification; Multiple themes on one card; Multiple icons; Sub-service creating a theme; Feature requesting custom UI outside framework. **Exceptions:** Goal is not to prevent exceptions but to control, contain and expire them.

**Observed themes in designs**

- **Base**: white card, no icon (Bike Taxi 8289:13187, Auto 8023:84682)
- **Sub-service**: white card + 72x82 top-right raster icon; chip icon tinted per sub-service (Scooty scooter, Grocery bag, Parcel bag, Food burger, Pet dog, XL black badge, AC blue badge, NCR, Zepto, Student auto, E-rick)
- **Premium/Priority (contextual)**: near-black header, gold chip text + gold fare, ₹/km EPKM, 3D gold star; cream body #fff2de (8289:10483, 8267:9358)
- **Company (contextual)**: blue header + businessman illustration, chip 'XL - Company' (7229:2421)
- **Intercity (contextual)**: sky/cloud gradient header, destination 'Varkala, Kerala' + '636 KM (6 Hrs 20min)' (6656:64164 variant 4, 5602:68807)
- **GTA (preference)**: pink header + pink-tinted body, heart map-pin icon, chip 'Bike -GTA'/'Go To Area' (8289:11283, 7474:5481); also GTA Tag row '15Km away from your Go To' (pink outline) on non-GTA themes
- **Seat Share/E-Rick**: teal gradient header + e-rick icon with label pill (9382:23398)
- **Tips**: green 'Customer added ₹20 extra' bar above CTAs (not a theme)

Earlier spec: 407:1548 text 'Detailed Order Accept Screen Combinations' (2024): 5 modifiers (New service, New rate card, Preference order, Extra earning, Tip) and all 32 combinations — superseded by the 2-signal rule of the 2026 framework.

## Comparison with Runway Card / ServiceChip / OAMessageBox / HomeOfOrders

- Card anatomy matches Runway .Base OA (Header > Location Details > Tips card/Extra card > CTAs > hidden Contextual Order Icon); widths drift: Runway 272, local OA set 264, older cards 268/260.
- Runway OA Cards is split by vehicle (Service=Bike/Auto/Cab OA, with 9-12 'Type' variants each); the framework and the local OA set (6656:64164) split by bucket (Type=Base Service | Sub Service | Contextual orders | Intercity) with booleans Extra Card/Gems/Tips/Payment Method. Runway has no theme/contextual variant (no header theme fill, no Company/Priority/Premium/GTA-theme), only GTA Tag row + 'Show Cab Extra Icon'.
- Runway .Service Chips (18 variants, single Sub-Service prop, labels 'Cab Eco', 'Auto Share') vs local Service Chip (6640:63378, Base Service x Sub Service, 16v incl. Intercity Eco/Pre/XL, Cab AC/Non-AC; no Corporate/Company, no Cab Share). Labels differ: 'Cab Non-AC' vs Runway 'Cab Economy'. Black chip (Scooty, Auto Plus) still used for premium sub-services even though framework says sub-services get icon only.
- Runway has no Service Icons set for the 72x82 OA icon with label pill; local Service Icons (6656:63909, Type New/Old x Service) and Runway assets/icons/service PNGs overlap.
- OAMessageBox / HomeOfOrders: this file's OA list screens use a header with VO toggle (local 'VO Toggle' 68x32, 14 variants) instead of Runway HomeOfOrders' remote 'Toggle ON' (66x32). Side-bar tabs O1/O2/O3 are local; Dev Ticket Aug '25 removes empty order placeholders (Runway HomeOfOrders still has 'Empty Order Bar'). No empty/off-duty state appears in this file.

## Pattern candidates

### OA card - bucketed theming
- When: Any incoming order alert card
- Structure: Card r16 white: Header[ServiceChip, Fare row(₹ base Bold32 + green '+extra' + (payment)), optional EPKM/destination] + right 72x82 icon slot > Route(dot-line-arrow) pickup km+address / drop km+address > optional tag row (GTA distance, Main Road Pick Up, pickup/drop tags) > optional tips bar > CTAs(Reject timer ring 48 + Accept fill)
- Components: Card/.Base OA, ServiceChip, Button
- Evidence: [8890:7129](https://www.figma.com/design/NjrI5wZ8ztYRZmUWBAPuDy/?node-id=8890-7129), [6656:64164](https://www.figma.com/design/NjrI5wZ8ztYRZmUWBAPuDy/?node-id=6656-64164), [8289:13187](https://www.figma.com/design/NjrI5wZ8ztYRZmUWBAPuDy/?node-id=8289-13187), [8289:10483](https://www.figma.com/design/NjrI5wZ8ztYRZmUWBAPuDy/?node-id=8289-10483), [8289:11283](https://www.figma.com/design/NjrI5wZ8ztYRZmUWBAPuDy/?node-id=8289-11283), [7229:2421](https://www.figma.com/design/NjrI5wZ8ztYRZmUWBAPuDy/?node-id=7229-2421), [9382:23398](https://www.figma.com/design/NjrI5wZ8ztYRZmUWBAPuDy/?node-id=9382-23398)
- Variations: Base (no icon/theme), Sub-service (icon), Contextual (header theme+icon: Premium/Priority dark-gold, Company blue, Intercity sky), Preference (GTA pink + heart pin)
- Conflicts: Runway Card variants are per-vehicle not per-bucket; Scooty/Auto Plus still themed black although sub-service; Parcel 'Icon+Theme' experiment violates 'sub-service creating theme'.

### Order list with side-bar order tabs
- When: Captain on duty with 1+ concurrent order alerts
